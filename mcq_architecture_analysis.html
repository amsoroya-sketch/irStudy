🔄 Request Flow: User → MCQ List

1 App.tsx User navigates to /mcqs
  • BrowserRouter intercepts route
  • ProtectedRoute checks authentication
  • Lazy loads MCQBrowser component
2 ProtectedRoute Authentication Check
  • Checks localStorage for accessToken
  • If missing → redirect to /login
  • If present → render child component
3 MCQBrowser.tsx Initialize and Fetch Data
  • useState for filters (category, difficulty, search, pagination)
  • useQuery hook calls getMCQs() from api/mcqs.ts
  • Axios adds Authorization header via interceptor
4 api/mcqs.ts → getMCQs() HTTP GET /api/v1/mcqs/
  • Base URL: http://localhost:8001/api/v1
  • Endpoint: /mcqs/ (note trailing slash)
  • Headers: Authorization: Bearer {token}
  • Query params: skip, limit, category, difficulty, search
5 Backend: mcqs.py list_mcqs() endpoint
  • Route: @router.get('/') → /mcqs/
  • Dependency: get_current_active_user (validates JWT)
  • Database: Query MCQ table with filters
  • Response: List[MCQPublic] (no answers)

🚨 Issues Identified

❌ Authentication Failure
Symptoms:
  • API returns 401 Unauthorized
  • User likely not logged in or token expired
  • Frontend shows empty state or loading spinner
Diagnosis:

Backend requires valid JWT token. API call failing at step 5.

Solution:

✅ User must login first at /login to obtain access token

❌ Backend Port Mismatch
Symptoms:
  • Two uvicorn instances running (port 8000 and 8001)
  • Frontend configured for port 8001 (VITE_API_BASE_URL)
Diagnosis:

Development environment has multiple backend instances

Solution:

✅ Ensure frontend points to correct backend (8001)

❌ Trailing Slash Redirect
Symptoms:
  • API redirects /mcqs to /mcqs/ (307 Temporary Redirect)
Diagnosis:

FastAPI router uses prefix='/mcqs' with route @router.get('/')

Solution:

✅ Not critical - axios follows redirects automatically

📦 Component Architecture Details

App.tsx
Root application component
Responsibilities:
  • Wrap app with ThemeProvider (Material-UI theme)
  • Wrap app with QueryClientProvider (React Query cache)
  • Wrap app with BrowserRouter (React Router)
  • Wrap app with AuthProvider (authentication context)
  • Define all routes with lazy loading
  • Show MobileBottomNav for mobile devices
Key Features:
  • Code splitting via lazy() for performance
  • LoadingFallback with CircularProgress for lazy routes
  • ProtectedRoute HOC for authenticated routes
MCQBrowser.tsx
Browse and filter MCQs catalog
State:
Filters: MCQListParams (skip, limit, category, difficulty, search)
Page: Current pagination page number
Api Integration:
Query Key: ['mcqs', filters]
Query Fn: getMCQs(filters)
Stale Time: 2 minutes
Cache: React Query handles caching, refetch, loading states
Ui Sections:
  • Header with title and 'Create MCQ' button (RBAC: MCQ_CREATE permission)
  • Filters: Search field, Category dropdown, Difficulty dropdown
  • Loading state: CircularProgress spinner
  • Error state: Alert with error message
  • MCQ Grid: Cards with difficulty chip, category chip, question preview, tags
  • Pagination: Material-UI Pagination component
  • Empty state: 'No MCQs found' message
Permissions Used:
  • MCQ_CREATE: Show 'Create MCQ' button
  • MCQ_ATTEMPT: Show 'Attempt' button on cards
  • MCQ_VIEW: Show 'View' button on cards
  • MCQ_UPDATE: Show 'Edit' button on cards
api/mcqs.ts
MCQ API client functions
Functions:
  • getMCQs(params): Fetch paginated MCQ list
  • getMCQById(id): Get single MCQ details
  • createMCQ(data): Create new MCQ (educator only)
  • updateMCQ(id, data): Update MCQ (educator only)
  • deleteMCQ(id): Delete MCQ (admin only)
  • submitMCQAttempt(data): Submit answer attempt
  • getRandomMCQ(specialty, difficulty): Get random MCQ
  • submitMCQAnswer(mcqId, attemptData): Submit answer with timing
  • getMCQStatistics(): Platform-wide MCQ stats
api/client.ts
Axios instance with auth and error handling
Config:
Baseurl: import.meta.env.VITE_API_BASE_URL || http://localhost:8001/api/v1
Timeout: 30 seconds
Headers: Content-Type: application/json
Request Interceptor:
  • Get accessToken from localStorage
  • Add Authorization: Bearer {token} header to all requests
Response Interceptor:
  • On 401 Unauthorized:
  • 1. Try to refresh token using /auth/refresh
  • 2. If refresh succeeds: retry original request
  • 3. If refresh fails: clear tokens and redirect to /login
Error Handling:
  • Network Error → 'Cannot connect to server'
  • Timeout → 'Request timeout. Please try again.'
  • Server error → Extract detail from response.data.detail
ProtectedRoute
HOC to protect routes requiring authentication
Logic:
  • Check if user is authenticated (useAuth hook)
  • If authenticated → render children
  • If not authenticated → redirect to /login
PermissionGuard
Component to conditionally render based on user permissions
Logic:
  • Check if current user has specified permission
  • If yes → render children
  • If no → render null (hide component)
🎯 Root Cause Analysis Summary
Primary Issue: Authentication Required The /api/v1/mcqs/ endpoint requires a valid JWT token (Bearer token in Authorization header).
Expected Behavior: When user is logged in, accessToken is stored in localStorage → axios interceptor adds it to request headers → backend validates token → returns MCQ list.
Actual Behavior: User likely not logged in or token expired → No/Invalid Authorization header → Backend returns 401 Unauthorized → Frontend shows error/empty state.
Resolution Steps:
  1. Navigate to http://localhost:5173/login
  2. Login with valid credentials (or register new account at /register)
  3. Upon successful login, accessToken saved to localStorage
  4. Navigate back to http://localhost:5173/mcqs
  5. MCQBrowser will fetch and display MCQs successfully
