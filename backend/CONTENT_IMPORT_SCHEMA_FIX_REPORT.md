```python

    RESPIRATORY = "respiratory"

    PSYCHIATRY = "psychiatry"
    ENDOCRINOLOGY = "endocrinology"

    GENERAL_PRACTICE = "general_practice"
    PAEDIATRICS = "paediatrics"  # ← Australian spelling
    OBSTETRICS_GYNAECOLOGY = "obstetrics_gynaecology"
```

## Known Limitations

### 1. SQLite JSON Support

**Issue**: SQLite doesn't support JSON column type natively (unlike PostgreSQL).

**Impact**: Test imports with SQLite show "type 'dict' is not supported" errors for JSON fields.

**Solution**: Production uses PostgreSQL which handles JSON natively - no issue in production.

**Workaround for Testing**: Convert JSON fields to JSON strings for SQLite:
```python
# For SQLite testing only
options_json = json.dumps(options) if using_sqlite else options
```

### 2. Duplicate Handling

**Current Behavior**: Script skips duplicates silently based on unique constraint (`question_id`, `osce_id`, `persona_code`).

**Limitation**: No warning if multiple JSON files contain same ID - first one wins.

**Recommendation**: Run deduplication check before import:
```bash
# Check for duplicate MCQ IDs
find data/mcqs/ -name "*.json" -exec jq -r '.mcqs[]?.id // .questions[]?.id' {} \; | sort | uniq -d
```

### 3. Missing Required Fields

**Current Behavior**: Script uses defaults or skips records with missing required fields.

**Defaults Applied**:
- `citation`: "Australian medical guidelines"
- `specialty`: `GENERAL_PRACTICE`
- `difficulty`: `MEDIUM`
- `question_text`: Extracted from nested structure or empty string

**Recommendation**: Validate JSON schema before import using `scripts/validate_content_mvp.sh`.
